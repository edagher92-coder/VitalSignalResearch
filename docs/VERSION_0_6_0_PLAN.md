# Evidessa Research 0.6.0 integration plan

Status: simulator-only release candidate work. This document does not authorize
personal collection, a deployed backend, model-generated output, attended
monitoring, public release, or clinical use.

## Release purpose

Version `0.6.0-research` is a reviewable integration checkpoint for:

1. a premium but safety-aware phone/prototype hierarchy;
2. transparent, typed explanation of the simulator forecast;
3. concern and abstention as total, non-leaking UI states;
4. app-release metadata and verification evidence tied to one commit; and
5. whole-system contract evaluation before runtime composition begins.

Existing package names, protocol routes, cryptographic identifiers, endpoint
definitions and signed schema versions remain stable technical identities.
An app release bump does not silently bump those contracts.

## Forecast explanation contract

- Locked, learning, abstained and concern-held states contain no probability,
  interval, base rate or explanation.
- A revealed point estimate and bounds come only from the prospective ledger
  projection.
- Explanation facts come from typed `ForecastDiagnostics` and the sealed
  feature snapshot. Hand-written numeric model claims are prohibited.
- The explanation separates:
  - unweighted fixture rate;
  - similarity/quality-weighted rate;
  - effect of the named Beta prior;
  - posterior point estimate;
  - engineering uncertainty method and quality penalty.
- Similarity is never presented as causality.
- The browser is labelled as a static fixture with no durable ledger.

## Motion contract

- Premium character comes from hierarchy, glass depth, spacing, one-shot card
  entrance and interruptible disclosure transitions.
- There is no continuous heartbeat, score pulse, “live” observer pulse,
  ambient drift, auto-advancing tour or celebratory health-result animation.
- Concern activation is immediate and removes all reassuring analytics.
- Android system animator scale and web reduced-motion preferences disable
  nonessential value/entrance transitions without hiding meaning.
- Safety, locked, unavailable and explanation surfaces retain readable opaque
  content regions and explicit text labels.

## Whole-system findings

The platform-neutral integrity core is substantial, but the following remain
uncomposed or contract-only:

- Health Services observation → durable watch batch → outbox;
- phone Data Layer runtime → Keystore-backed encrypted sink at app startup;
- durable ingestion ledger → metric windows → analytics;
- encrypted concern/forecast journals in the default phone composition;
- observer HTTP service, durable idempotency/audit stores and portal;
- Kotlin/OpenAPI observer projection and all ten availability states;
- assistant gateway active-release binding and HTTP transport; and
- exact-device Samsung/public sensor validation.

These are explicit next work packages, not implied capabilities of 0.6.

## Backend and AI decision

The backend remains a non-deployed OpenAPI contract. A future observer vertical
slice must first align shared identifiers, request-body digests, idempotency,
observer coverage, concern projection and `VALIDATION_BLOCKED`.

Runtime AI remains disabled. The approved architecture is a fixed, bounded
explanation workflow—not an autonomous agent:

`authoritative packet → signed release → one structured selection → deterministic verification → durable audit → reviewed local copy`

No runtime tools, browsing, memory, autonomous loops, treatment actions, alerts,
free clinical prose or automatic provider failover are authorized.

## Acceptance gates

- Prototype source contracts, JavaScript syntax and browser interaction pass.
- Structural/safety validator scans tracked files and passes with ordinary
  gitignored Android setup files present.
- Core and Android unit tests pass.
- Phone and Wear Compose compile with the pinned SDK/AGP.
- Android lint and both debug APK assemblies pass from one clean commit.
- APK manifests report version code 6 / `0.6.0-research`; both APKs verify with
  the same signer.
- Concern-after-reveal exposes no numeric forecast in state or UI.
- Repeated check-in remains idempotent and internally consistent.
- DEVELOPING and STEADY explanations name their actual matched neighborhoods.
- Prototype/monitoring contracts expose all ten freshness/validation states.
- Reduced-motion and custom dialog keyboard behavior are exercised, not merely
  detected by source-string tests.

Physical phone/watch pairing, personal data, reference-device accuracy,
Samsung AARs, production signing and deployed backend/AI remain separate NO-GO
evidence gates.
