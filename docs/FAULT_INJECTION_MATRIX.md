# VitalSignal v0.6 fault-injection matrix

Source-review checkpoint: 2026-08-23. This is a private-pilot gate, not evidence of clinical safety or production readiness.

**Status language:** **Covered (JVM)** means a current deterministic unit/integration test asserts the stated narrow invariant. **Partial (JVM)** means only a nearby or simulated failure is tested. **Missing** means there is no current automated test for the fault. The Android/physical column is independent: JVM coverage is not evidence that Wear OS, Data Layer, Keystore, filesystem, process-death, backup, or exact Samsung hardware behaves correctly.

## Receipt, ordering and lifecycle

| ID | Injection point | Expected invariant / result | Automated status | Android / physical status |
|---|---|---|---|---|
| RX-01 | Sink rejects or throws before durable commit | NACK only; no durable token; never emit ACK; quarantine attempt is explicit | **Partial (JVM):** `acknowledgementExistsOnlyAfterDurableCommit`; simulated failure, not process death | **Pending:** kill process at each real write/fsync boundary |
| RX-02 | Process dies after phone commit but before ACK is delivered | Committed bytes survive; identical retry returns `DURABLE_DUPLICATE` with the same durable token; no second record | **Covered (JVM):** `commitBeforeAckSurvivesRestartAndLostAckIsIdempotentlyReissued` | **Pending:** phone force-stop/reboot and Data Layer ACK loss |
| RX-03 | Identical batch delivered repeatedly or after delay | Exactly one durable record; every verified retry may be idempotently ACKed | **Covered (JVM):** receiver duplicate test and encrypted-journal restart test | **Pending:** repeated Data Layer redelivery on paired devices |
| RX-04 | Existing batch ID reused with different canonical bytes | `ID_CONFLICT` NACK and quarantine; canonical record unchanged | **Covered (JVM):** receiver conflict test and append-only-store duplicate conflict test | **Pending:** real receiver and encrypted phone storage |
| RX-05 | Higher source ordinal arrives before a delayed, unused lower ordinal | The ordinal policy introduced in v0.3 and retained in v0.6 accepts both if `(device, session, sequence)` ordinals do not overlap | **Covered (JVM):** `delayedNonOverlappingOrdinalIsAcceptedButReusedOrdinalIsRejected` | **Pending:** document and verify intended Data Layer retry ordering |
| RX-06 | Different batch reuses an already committed `(device, session, sequence)` | NACK; no overwrite and no second durable acceptance | **Covered (JVM):** delayed/overlap encrypted-journal test | **Pending:** paired-device concurrency/redelivery |
| RX-07 | Gap, replay or out-of-sequence local journal record | Do not advance the append-only chain; quarantine or block append | **Covered (JVM):** `gapsReplaysAndOutOfOrderSequencesDoNotAdvanceTheLedger` | **Pending:** app process/reboot recovery on Android filesystem |
| RX-08 | ACK is NACK, or batch/session/sequence/wire digest differs from queued item | Watch must not authorize outbox deletion | **Covered (JVM):** `nackAndEveryIdentityMismatchDenyDeletion` | **Pending (device):** receipt listener/outbox adapters exist in source; no paired-device result |
| RX-09 | Same ACK receipt is replayed, including after replay-store reconstruction | First exact ACK may authorize once; replay never authorizes deletion | **Covered (JVM):** outbox replay test plus `claimSurvivesRestartAndCannotMoveToAnotherBatch` | **Pending:** Wear OS Keystore-backed replay store and reboot test |
| RX-10 | Replay-claim store fails | Deny deletion; retain queued batch | **Covered (JVM):** `replayStoreFailureCannotAuthorizeDeletion` | **Pending:** storage/Keystore failure on watch |
| RX-11 | Process dies after durable replay claim but before queued-file deletion | Batch remains recoverable; staged deletion survives and resumes without allowing a different receipt to delete it | **Covered (JVM):** `onlyExactAuthenticatedAckDeletesAndFailedRemoteDeleteSurvivesRestart` | **Release-blocking pending:** kill/reboot at every physical deletion boundary |
| RX-12 | New packet arrives while an older batch is being deleted | Atomic queue update: neither new nor old unacknowledged data is removed | **Missing** | **Release-blocking pending:** concurrent Wear OS service/outbox test |
| RX-13 | Watch is offline, phone unavailable, or Data Layer stalls | Retain the encrypted outbox within a defined capacity; persist bounded deterministic retry without claiming “synced” | **Covered (JVM):** failed enqueue and retry timing survive outbox restart; record/byte limits fail closed | **Release-blocking pending:** airplane mode, Bluetooth loss, phone reboot and long-duration capacity behavior |
| RX-14 | Phone commits a batch but the ACK key/radio/process is unavailable before receipt delivery | Stage the exact consent-generation/node/path/batch/ACK binding in encrypted storage before radio; recover it after restart and retry only when eligible | **Covered (JVM):** `publisherFailureIsEncryptedAndRecoveredAfterProcessShapedRestart` and `missingAcknowledgementKeyRemainsPendingUntilKeyRecovery` | **Release-blocking pending:** compose and execute the Android worker, reboot/key-unlock and connectivity hooks on paired devices |
| RX-15 | Consent rotates while a phone receipt is pending, or publisher failure persists | Never send a stale generation; make withdrawal/rotation terminal; stop after the finite attempt bound and retain auditable terminal state | **Covered (JVM):** `consentRotationTerminatesStaleGenerationWithoutPublishing` and `publisherFailuresHaveFiniteAttemptsAndDoNotRetryAfterExhaustion` | **Release-blocking pending:** physical consent/key rotation, long-offline and retry-exhaustion UX |
| RX-16 | Radio accepts a receipt and the process dies before the delivered marker commits | Do not claim a known terminal state; retain pending and permit an at-least-once duplicate that the watch replay gate must safely reject | **Covered (JVM):** `crashShapedGapAfterRadioSendBeforeDeliveredMarkerRetriesAtLeastOnce` | **Release-blocking pending:** kill the phone process at the real MessageClient/append boundary |
| RX-17 | Watch is low, charging, thermally limited, off wrist, or reports unknown thermal/contact state | Open an explicit missing interval; never impute normal; pause or fail closed according to the exact state | **Covered (JVM):** continuity pause/unknown-state tests and adaptive-capture gate test | **Release-blocking pending:** exact Android callbacks, threshold characterization and long-duration hardware execution |
| RX-18 | Watch process dies, battery drains/reboots, wall clock changes, or consent changes | Recover only an authenticated gap-free journal; preserve next sequence/provenance; require exact same-generation resume permit; reject unsafe/changed consent | **Covered (JVM):** continuity battery/reboot, process, clock/consent and tamper tests | **Release-blocking pending:** Keystore/boot/WorkManager composition and physical kill/drain/reboot/clock tests |

## Authentication, keys and wire corruption

| ID | Injection point | Expected invariant / result | Automated status | Android / physical status |
|---|---|---|---|---|
| CR-01 | Unknown or retired transport key ID | `UNKNOWN_KEY` NACK; quarantine; authenticator must not pass plaintext to commit | **Covered (JVM):** authenticated receiver unknown-key test | **Pending:** real pairing/key resolver |
| CR-02 | Wrong storage key ID or wrong secret with the same ID | Recovery accepts nothing, quarantines the file, and blocks new appends | **Covered (JVM):** `wrongKeyIdAndTamperingAreQuarantinedAndNeverAccepted` | **Pending:** Android Keystore invalidation and restore behavior |
| CR-03 | Key rotation during queued transfer | Old queued data remains decryptable for a bounded grace period, new writes use the new key, and retirement is auditable | **Missing:** no rotation/migration protocol or dual-key test | **Release-blocking pending** |
| CR-04 | AES-GCM tag or ciphertext bit flip | Authentication failure; no durable batch commit and no ACK | **Covered (JVM):** authenticated-payload tamper test; receiver metadata/authentication rejection | **Pending:** tamper actual Data Layer payload |
| CR-05 | Batch/session/device/sequence/time/schema/content-type metadata changed while ciphertext is retained | AAD authentication fails; no commit and no ACK | **Partial (JVM):** session/routing-metadata tamper is asserted; every AAD field is included in code but is not individually mutated by tests | **Pending:** paired-device injection |
| CR-06 | Attacker changes ACK identity and recomputes its unkeyed inner SHA-256 | Outer HMAC-SHA-256 fails; no deletion authorization and no replay claim | **Covered (JVM):** `recomputedInnerChecksumCannotForgeOuterAuthentication` plus authenticated outbox test | **Pending:** physical ACK key provisioning/rotation and listener wiring |
| CR-06 | Encrypted payload key ID or nonce bytes changed | Unknown-key or authentication failure; never commit | **Partial (JVM):** unknown key and generic ciphertext/AAD tamper covered; key-ID/nonce mutations are not individually asserted | **Pending** |
| WR-01 | Outer-envelope checksum bit flip | `CHECKSUM_MISMATCH` NACK; commit is never called | **Covered (JVM):** envelope codec and receiver corruption tests | **Pending:** Data Layer receiver |
| WR-02 | Truncated envelope or ACK | Strict decode failure; no commit; malformed ACK cannot authorize watch deletion | **Partial (JVM):** truncated envelope and tampered encoded ACK are asserted; truncated ACK is not a dedicated fixture | **Pending:** truncated Data Layer payload |
| WR-03 | Valid envelope/ACK followed by trailing bytes | `TRAILING_BYTES` or invalid-ACK denial; never commit/delete | **Covered (JVM):** envelope/ACK codec tests | **Pending** |
| WR-04 | Envelope, ACK, encrypted payload or local payload exceeds configured bound | Reject before durable acceptance; do not create a committed file | **Partial (JVM):** outer-envelope/store bounds plus the 64 KiB ordinary-DataItem budget are asserted before durable watch enqueue; ACK and every inner-payload maximum are not dedicated fixtures | **Pending:** DataMap framing, memory and radio limits on exact devices; larger Asset/chunk path is absent |

## Durable storage, recovery and privacy

| ID | Injection point | Expected invariant / result | Automated status | Android / physical status |
|---|---|---|---|---|
| ST-01 | Storage full, quota exceeded, read-only filesystem or `ENOSPC` during temp write/fsync/rename | No ACK; committed chain remains recoverable; temp artifact cannot become a record; user sees storage-unavailable state | **Missing:** generic sink failure is simulated, but filesystem-full stages are not injected | **Release-blocking pending** |
| ST-02 | Partial `.tmp` file remains after crash | Ignore as uncommitted; never recover or ACK it; next valid sequence may commit | **Covered (JVM):** `partialTemporaryFileIsIgnoredAcrossRestartAndCannotBecomeARecord` | **Pending:** kill during each Android file operation |
| ST-03 | Earlier committed journal file is deleted, leaving a gap | Accept no later chain as canonical; quarantine/block append | **Covered (JVM):** `missingEarlierCommittedSequenceQuarantinesTheRemainingChain` | **Pending:** Android filesystem test |
| ST-04 | Committed batch, receipt-delivery or forecast-audit file is modified/truncated | Recovery fails closed; new data is not ACKed; pending delivery/forecast state becomes unavailable rather than reconstructed from guesses | **Covered (JVM):** tampered batch/receipt journal, malformed file and unreadable/corrupt forecast recovery tests | **Pending:** on-device corruption and recovery UI |
| ST-05 | Process starts before first user unlock; Keystore key unavailable | Collect/transfer state must be explicitly locked or unavailable; no plaintext fallback, silent reset or false ACK | **Missing** | **Release-blocking pending:** direct boot, first unlock, reboot, lock-screen tests |
| ST-06 | Two processes/instances append concurrently | One atomic winner; no duplicate sequence, overwrite or split-brain recovery | **Missing:** store documents that a production process-wide lock is still required | **Release-blocking pending** |
| ST-07 | App uninstall/reinstall, clear-data, key loss or device restore | Old ciphertext must not be misread; user is told data/key continuity was lost; no baseline or calibration silently survives as valid | **Missing** | **Release-blocking pending** |
| PR-01 | Sensitive values searched in committed encrypted forecast and receipt-delivery files | Unique outcome/model/probability and receipt session/token fixture strings are absent from ciphertext files | **Covered (JVM):** encrypted forecast and `encryptedJournalDoesNotExposeReceiptIdentityOrTokensAsPlaintext` tests; this is narrow, not a forensic audit | **Pending:** inspect phone/watch files, tombstones and memory artifacts |
| PR-02 | Runtime logging, exception, notification or analytics path receives health payload | No raw sensor, symptom, forecast, key, nonce or direct identifier in logcat/crash/analytics output | **Missing:** source has no obvious logging calls, but there is no automated sink/logcat leak test | **Release-blocking pending** |
| PR-03 | Android backup/device-transfer request | Health stores and keys are excluded; restoration cannot create readable orphaned ciphertext or stale “calibrated” state | **Partial (static):** both manifests set `android:allowBackup="false"`; no backup/restore execution test | **Release-blocking pending:** `adb backup`/device-transfer/OEM restore verification |

## Time, forecast locking and abstention

| ID | Injection point | Expected invariant / result | Automated status | Android / physical status |
|---|---|---|---|---|
| TM-01 | Wall clock moves backward/forward, receipt timestamps repeat, or clock is corrected after offline capture | No duplicate receipt authority, early reveal, negative duration or silent reordering; retain original UTC and provenance | **Missing:** only non-negative/chronology guards exist; no clock-jump state-machine test | **Release-blocking pending** |
| TM-02 | Timezone/DST/travel changes local date or hour bucket | Recompute matched baseline context deliberately; never merge mismatched local-hour history or double-count a DST hour | **Partial (JVM):** wrong-hour/future baseline windows are excluded; timezone conversion and DST transitions are untested | **Pending:** Sydney DST plus travel/timezone tests |
| TM-03 | Future-dated sensor/history sample enters baseline or forecast training | Exclude it; it cannot mature the baseline or train the forecast | **Covered (JVM):** robust-baseline and personal-forecast future-data tests | **Pending:** real Samsung timestamps/clock skew |
| FC-01 | Forecast committed but pre-reveal check-in is absent | Probability and bounds remain structurally unavailable; reveal is rejected | **Covered (JVM):** locked-view field inspection and chronology test | **Pending:** Compose UI, accessibility tree, notification and log leakage |
| FC-02 | Audit append fails or recovered audit chronology is unreadable | Keep last durable state; return unavailable/abstaining view; never reconstruct or reveal from volatile state | **Covered (JVM):** crash-before-append and corrupt/unreadable recovery tests | **Pending:** Android process-death and storage-error UI |
| FC-03 | Low quality, immature baseline, firmware transition or wide uncertainty | Produce learning/unavailable/abstained/remeasure state; do not expose a health forecast | **Covered (JVM):** safety-policy, forecast-engine and simulator low-quality tests | **Pending:** end-to-end physical sensor-quality/firmware cases |
| FC-04 | Out-of-distribution context | Abstain and withhold interpretation/forecast | **Missing:** policy branch exists, but no direct OOD test fixture asserts it | **Release-blocking pending** |

## Private-pilot unlock criterion

The pilot remains **locked** until every release-blocking row above has an executable test and the full matrix passes on the exact supported phone/watch pair, Android/Wear OS versions, Samsung SDK versions and firmware. A JVM pass alone cannot unlock personal-data collection.

Across all injected trials, restarts and retries, the required result is absolute:

1. **Zero false ACKs:** no ACK unless the exact authenticated canonical batch is durably committed and recoverable.
2. **Zero silent loss:** no unacknowledged watch batch is deleted, overwritten or abandoned without an explicit recoverable/quarantined state.
3. **Zero locked-forecast leakage:** before the prospective check-in and authorised reveal, probability and bounds appear nowhere in UI state, accessibility output, notifications, logs, analytics, exports or recoverable plaintext.
4. **Abstain on uncertainty:** low quality, immature baseline, wide intervals, firmware/schema transition, OOD input, unreadable audit state or unavailable key/storage produces abstention/unavailable—not a health interpretation or forecast.

A single violation fails the pilot gate. Passing this engineering gate still does **not** establish medical validity, emergency-monitor reliability, life-saving capability or commercial release readiness.
